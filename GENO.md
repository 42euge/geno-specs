# geno-specs — Structured Execution Specs

`geno-specs` creates, manages, and validates structured specs — execution blueprints detailed enough for coding agents or dev loops to run autonomously. A spec goes beyond a task: it declares inputs, outputs, steps, validation checks, and agent requirements.

## Skills

| Skill | Slash command | Purpose |
|-------|---------------|---------|
| geno-specs | — | Umbrella |
| geno-specs-create | /geno-specs-create | Interactive spec authoring |
| geno-specs-list | /geno-specs-list | List specs with filters |
| geno-specs-show | /geno-specs-show | Display spec contents |
| geno-specs-run | /geno-specs-run | Execute a spec |
| geno-specs-validate | /geno-specs-validate | Run completion checks |


## Project scaffolding (`init`)

`geno-specs init` creates `.specs/VISION.md`, `TENETS.md`, `GOALS.md`, and
`features/` in the current repo. By default these are bare placeholders
(headers + HTML-comment prompts).

`geno-specs init --fill` drafts real content instead, using only local
signal (no LLM call, no API keys required):

- **VISION.md** — pulls the README's opening description/purpose paragraph
  into "Why this exists".
- **GOALS.md** — summarizes the last ~15 `git log` commit subjects into
  "Active".
- **TENETS.md** — seeds two generic, project-agnostic starter principles
  ("prefer explicit over implicit", "small isolated units").

Every filled section is marked `> DRAFT — generated by geno-specs init --fill`
so it's clearly a draft to review, not finished prose. `init` never
overwrites a file that already exists, with or without `--fill`. This works
in any repo geno-specs is installed into, not just this one — it shells out
to `git log` in the target repo's cwd and reads its own README.md.

Implemented in `geno_specs/scaffold.py` (`scaffold()`, `_read_readme()`,
`_read_recent_commits()`) and wired into the `init` command in `cli.py` via
the `--fill` flag.

## Spec lifecycle

```
draft → ready → running → done
                       → failed → ready (retry)
Any state → abandoned
```
